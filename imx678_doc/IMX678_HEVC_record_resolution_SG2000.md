# IMX678 5MP HEVC 录像分辨率上限（SG2000 / sample_sensor_lcd_hevc）

## 适用范围

| 项目 | 说明 |
|------|------|
| 板卡 | Zonhor SG2000（CV181X） |
| 传感器 | IMX678，`imx678-mode 5m`（中心裁切 **2880×1620**） |
| 样例 | `sample_sensor_lcd_hevc` |
| 管线 | VI → VPSS Grp0 Chn0（NV12 + **ROT90**）→ VENC H.265 |
| 验证日期 | 2026-07-18，板子 `192.168.100.141` |

预览路径（320×192 → LCD）与录像路径独立；**预览正常不代表录像分辨率可用**。

---

## 症状（踩坑表现）

在 `imx678-mode 5m` 下启动 `sample_sensor_lcd_hevc` 并录像：

| 现象 | 典型值 |
|------|--------|
| `.h265` 文件极小 | ~130 KB（5 秒） |
| 转 MP4 后几乎无码率 | ~245 kbit/s（正常约 6 Mbit/s） |
| 画面 | 全黑 + 左侧洋红色竖条（YUV stride/旋转路径损坏的典型表现） |
| ffprobe 分辨率 | 可能仍显示 1620×2880，**元数据正确不代表内容有效** |

1080p 模式（`imx678-mode 1080p`）下录像正常（~3–4 MB / 5 s）。

---

## 根因

1. **全分辨率竖屏录像不可用**  
   对传感器全尺寸 **2880×1620** 做 VPSS `ROTATION_90` 再 `VPSS_Bind_VENC`，在 SG2000 上输出损坏帧。  
   与「仅差 8 像素对齐」无关：试过 **2880×1616**（高度 8 对齐）仍失败。

2. **硬件宽度硬上限约 2878**  
   扫频结论：**预旋转（横屏）宽度 ≥ 2880 必失败**；与高度无关（2880×1600 也失败）。  
   最大可用预旋转尺寸：**2878×1620** → 竖屏 **1620×2878**（约 **4.66 MP**）。

3. **1080p 模式无此问题**  
   传感器 1920×1080，ROT90 后 1080×1920，尺寸与带宽均在稳定范围内。

---

## 扫频结果（5MP 传感器，竖屏输出 = 预旋转宽高互换）

判定标准：3 s 自动录像，文件 **> 500 KB** 且画面非黑屏为 **OK**。

### 可用分辨率（节选）

| 预旋转（横屏） | 竖屏录像 | 像素 (MP) | 结果 | 备注 |
|---------------|---------|-----------|------|------|
| **2848×1602** | **1602×2848** | **4.56** | **OK** | **严格 9:16 最大可用（默认）** |
| 2878×1620 | 1620×2878 | 4.66 | OK | 非严格 9:16，像素更多 |
| 2816×1584 | 1584×2816 | 4.46 | OK | 标准 16:9 QHD+ |
| 2752×1548 | 1548×2752 | 4.26 | OK | |
| 2688×1512 | 1512×2688 | 4.07 | OK | |
| 2560×1440 | 1440×2560 | 3.69 | OK | 2K/QHD |
| 2048×1152 | 1152×2048 | 2.36 | OK | |
| 1920×1080 | 1080×1920 | 2.07 | OK | 兜底 |

### 失败分辨率（节选）

| 预旋转 | 竖屏 | 结果 | 说明 |
|--------|------|------|------|
| **2880×1620** | 1620×2880 | **FAIL** | 原生 5MP，~93 KB |
| 2880×1616 | 1616×2880 | FAIL | 8 像素对齐仍失败 |
| 2880×1600 | 1600×2880 | FAIL | 宽度 2880 即失败 |
| 2879×1619 | — | NOFILE | VPSS/VENC 初始化失败（非对齐尺寸） |

### 规律小结

```
预旋转宽度 < 2880  → 可能可用（需实测）
预旋转宽度 ≥ 2880  → 必失败
严格 9:16 最大可用   → 2848×1602（竖屏 1602×2848，默认）
非 9:16 像素上限     → 2878×1620（竖屏 1620×2878）
标准 16:9 最大       → 2816×1584（竖屏 1584×2816）
```

## 当前软件策略（`sample_sensor_lcd_hevc`）

5MP 模式下**预览仍用全传感器 2880×1620**；录像时 VPSS 先**下采样**再 ROT90，按档位自动选最大可用分辨率：

| 档位名 | 预旋转 | 竖屏录像 (9:16) | 约 MP | 说明 |
|--------|--------|----------------|-------|------|
| **`9:16-max`（默认）** | **2848×1602** | **1602×2848** | **4.56** | **严格 9:16 下实测最大可用** |
| `QHD+` | 2816×1584 | 1584×2816 | 4.46 | 标准 QHD+ |
| `2K/QHD` | 2560×1440 | 1440×2560 | 3.69 | |
| `1080p` | 1920×1080 | 1080×1920 | 2.07 | 兜底 |

> **非 9:16 的像素上限**：2878×1620 → 1620×2878（~4.66MP，略宽于 9:16）可用，但默认已改为严格 9:16。调试：`sample_sensor_lcd_hevc -e 2878x1620`。

码率随像素数相对 1080×1920 自动放大（默认 CBR 基准 6000 kbps）。

相关代码：

- `cvi_mpi/sample/sensor_lcd_hevc/sample_sensor_lcd_hevc.c` — `g_5m_enc_tiers[]`、`enc_pick_5m_tier()`
- `cvi_mpi/sample/sensor_lcd_hevc/hevc_recorder.c` — VENC 创建与码流写盘

## 使用与验证

### 模式切换

```bash
imx678-mode 5m
killall sample_sensor_lcd_hevc sample_sensor_lcd 2>/dev/null
sample_sensor_lcd_hevc
```

切换 `imx678-mode` 后**必须重启** camera 进程。

### 自动录像测试（无 LCD 操作）

```bash
sample_sensor_lcd_hevc -r 5 -o /tmp
ls -lh /tmp/rec_*.h265
# 5MP 期望：数 MB 级；若仅 ~100 KB 则分辨率/管线仍有问题
```

### 手动指定下采样分辨率（调试）

```bash
sample_sensor_lcd_hevc -e 2878x1620 -r 5 -o /tmp   # 最大
sample_sensor_lcd_hevc -e 2816x1584 -r 5 -o /tmp   # 标准 16:9
sample_sensor_lcd_hevc -e 2880x1620 -r 5 -o /tmp   # 应失败，用于对比
```

### PC 端查看

```bash
./cvi_mpi/sample/sensor_lcd_hevc/h265_to_mp4.py rec_YYYYMMDD_HHMMSS.h265
ffprobe -select_streams v:0 -show_entries stream=width,height rec_*.h265
```

## 误判与勿踩坑

| 误判 | 实际情况 |
|------|----------|
| 「5MP 模式录像应是 1620×2880」 | 原生该分辨率在 SG2000 上**不可用** |
| 「文件有分辨率元数据就是好的」 | 损坏管线仍可产出带 SPS 的小文件 |
| 「把高度对齐到 8 像素即可」 | 2880×1616 仍失败；瓶颈在**宽度 ≥2880** |
| 「预览正常说明录像也该正常」 | 预览走 320×192 支路，与 VENC 全尺寸旋转无关 |
| 「码率低是码率设太小」 | 黑场 HEVC 极低码率是**症状**不是根因 |

## 后续若需突破 1620×2878

| 方向 | 说明 |
|------|------|
| 横屏录制 2880×1620（不 ROT90） | 需改产品形态或后处理旋转 |
| 换编码路径 | 例如 CPU 送帧、GDC 旋转、双 Pass VPSS |
| 向 CVITEK 确认 | VPSS ROT90 + VENC 在 width=2880 的限制是否为芯片规格 |

在现有 **VPSS ROT90 + 硬件 VENC bind** 架构下，**1620×2878 即为实测上限**。
